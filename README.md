# GitLume

> 不用记任何 Git 命令的 Windows 桌面 Git 客户端。选文件夹 → 填备注 → 一键提交推送，其余全部自动完成。

---

## 一、功能特性

- **智能初始化**：选中项目文件夹后自动判断 Git 状态，未初始化自动执行 `git init`，首次提交自动合并云端历史
- **全局配置自动保存**：填一次用户名/邮箱，离开输入框即写入全局配置，所有操作自动带上
- **多仓库同时推送**：可添加多个远程仓库，一键同时上传到所有仓库；一个失败不影响其他仓库继续推送
- **每个仓库独立账号**：不同仓库可用不同用户名密码，登录时窗口明确提示当前仓库名和 URL
- **密码加密存储**：记住的密码以 XOR+Base64 混淆加密写入本地配置文件，推送时自动解密使用
- **HTTP 代理支持**：可配置代理端口（默认 7897），开关一键启用/关闭，解决 GitHub 等平台访问问题
- **智能交互**：禁止弹出 VIM 编辑器；禁止 Git Credential Manager 弹出白色系统对话框；认证失败自动弹窗重试
- **Git 命令超时保护**：所有 Git 操作 120 秒超时自动终止，避免网络卡死永久挂起
- **配置防抖保存**：停止输入 500ms 后自动写盘，避免每敲一个字符就写一次磁盘
- **自动日志限流**：日志超过 600 行自动裁剪最旧的 200 行，长期运行不卡顿
- **自动配置恢复**：关闭后下次打开自动恢复用户名、邮箱、仓库列表、代理设置
- **全程日志反馈**：每一步执行的 git 命令和结果实时显示，出错有清晰中文提示

## 二、技术亮点

### 自绘 GDI+ 控件体系
完整的自绘控件集（`SciPanel` / `SciButton` / `SciField` / `SciProgressBar`），全部使用 `System.Drawing` 手工绘制：
- **双缓冲 + `UserPaint`** 样式，避免闪烁
- **抗锯齿圆角矩形**（`GraphicsPath` + `SmoothingMode.AntiAlias`）
- **静态字体缓存**，避免 OnPaint 中反复创建 GDI Font 对象
- 进度条 40ms 定时器驱动流动光带动画，控件销毁时自动释放 Timer

### 基于 URL 注入的临时认证作用域
推送/拉取时，将凭据临时嵌入远程 URL（`https://user:pass@host/repo.git`），操作完成后立即恢复原始 URL：
- 凭据**仅存在于内存**，绝不写入 `.git/config`
- 每个远程仓库独立凭据，互不干扰
- 认证失败自动弹窗重试，通过后自动通知保存

### Git 进程隔离与防护
- 设置 `GIT_EDITOR=true` / `GIT_TERMINAL_PROMPT=0` / `GCM_INTERACTIVE=never` 环境变量，彻底屏蔽交互式弹窗
- 异步读取 stdout/stderr，防止输出量大使进程死锁
- 120 秒超时 + 强制 Kill，防止网络问题永久阻塞
- 应用退出时调用 `KillCurrent()`，不留孤儿进程

### 配置持久化与防抖
- 所有配置（用户名、邮箱、仓库列表、加密密码、代理设置）保存在 `config.json`，与 EXE 同目录，不往系统盘写任何文件
- 旧版 `%APPDATA%` 配置首次运行时自动迁移
- 输入变化触发 500ms 防抖 Timer，停止输入后才写盘，兼顾实时性与磁盘寿命

## 三、环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / Windows 11 |
| Git | 已安装 [Git for Windows](https://git-scm.com/download/win)（命令行 `git --version` 可用） |
| 运行 | .NET 8 运行时（或更高，自动向上兼容） |
| 源码构建 | .NET 8/9 SDK 或 Visual Studio 2022（17.8+） |

## 四、构建与运行

### 方式一：Visual Studio 2022

1. 安装 VS2022 并勾选「.NET 桌面开发」工作负载
2. 双击打开 `GitLume.sln`
3. 按 `F5` 直接运行

### 方式二：命令行

```bash
dotnet build GitLume/GitLume.csproj -c Debug
dotnet run --project GitLume/GitLume.csproj
```

### 方式三：一键启动

双击根目录的 `启动GitLume.bat`，自动检测 Git、自动编译、启动软件。

## 五、快速上手

1. 顶部「全局配置」填好 **用户名** 和 **邮箱**（离开输入框自动保存，填一次即可）
2. 点「选择...」选中你的 **项目文件夹**（软件会自动判断 Git 状态）
3. 在「本次修改的备注」里写一句说明（如：更新了登录功能）
4. 点 **「提交并推送」** —— 其余全部自动完成！

> 之后的每一次更新，重复第 2、3、4 步即可。不用管初始化、不用管拉取、不用管推送命令。

## 六、多仓库账号与密码

- 每个远程仓库可以**独立记住用户名密码**：推送时若某仓库需要登录，会弹出窗口并标明「正在为哪个仓库（名称 + URL）输入凭据」
- 勾选「记住密码」后，该仓库的密码会以 **XOR + Base64 混淆加密** 存入配置文件；下次推送到该仓库自动使用，不再弹窗
- 若某个仓库公开、无需认证，或凭据已正确保存，则**全程不会弹窗**
- 如果密码输错，认证失败后**不会保存错误密码**，避免下次卡死

## 七、数据文件

软件运行产生的所有文件都在**软件所在目录**，不向 C 盘写入任何内容：

| 文件 | 说明 |
| --- | --- |
| `config.json` | 配置：用户名、邮箱、仓库列表、加密密码、代理设置 |
| `crash.log` | 仅在程序异常崩溃时生成（正常使用不会出现） |

操作日志只在界面内存中显示，点击「清空日志」即可释放。

## 八、常见问题

- **编译报错 / dotnet 找不到**：请安装 .NET 8 SDK，或用 VS2022 打开 `GitLume.sln` 编译
- **推送提示认证失败**：在弹窗中确认当前仓库的用户名密码是否正确（Gitee 通常为用户名 + 密码或私人令牌；GitHub 推荐使用 Personal Access Token）
- **GitHub 推送失败（Connection reset / 无法连接）**：在软件中勾选「HTTP 代理」并填写代理端口（Clash 默认 7890，V2rayN 默认 10809），然后重试
- **AtomGit / GitCode 推送失败（Access denied）**：GitCode 已废弃密码认证，请使用 [Personal Access Token](https://gitcode.com/user/settings/access_tokens) 作为密码
- **第一次推送提示合并**：属正常现象，软件会自动处理云端已有内容与本地历史的合并
- **出现白色系统登录框**：已默认禁用 Git Credential Manager，如仍有弹出请确保使用最新版本
